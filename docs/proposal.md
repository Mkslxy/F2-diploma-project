# Thesis Proposal / Концепція кваліфікаційного проєкту

## 1. Робоча назва проєкту (Project Title)
* **Українською:** Розробка масштабованої подієво-керованої (Event-Driven) екосистеми для мультинаціонального маркетплейсу
* **English:** Engineering of a Scalable Event-Driven Ecosystem for a Multinational Marketplace

## 2. Актуальність та проблематика (Relevance and Problem Statement)
В умовах глобалізації електронної комерції сучасні мультинаціональні платформи стикаються з нерівномірними піковими навантаженнями, транскордонною гетерогенністю каталогів та високою вартістю затримок (latency) транзакцій. Класичні синхронні монолітні та сервіс-орієнтовані архітектури призводять до виникнення каскадних відмов (cascading failures), деградації продуктивності та проблем узгодженості даних у розподілених сховищах під час паралельної обробки замовлень. 

Інженерна складність полягає у забезпеченні суворої консистентності бізнес-операцій (Eventual Consistency) між незалежними сервісами, гарантуванні доставки повідомлень (At-Least-Once Delivery) без ризику дублювання транзакцій та реалізації відмовостійких контурів безперервної обробки потоків подій у режимі реального часу.

## 3. Сформована ідея продукту (Product Concept & Architecture)
Програмна система являє собою хмароорієнтовану подієво-керовану (Event-Driven) мікросервісну платформу, побудовану на основі ізольованих сховищ (Database per Service) та асинхронного брокера повідомлень. 

Архітектурний каркас базується на принципах CQRS (Command Query Responsibility Segregation) для оптимізації читання/запису, патерні Transactional Outbox для атомарної публікації подій та оркестрованій Saga для проведення розподілених транзакцій (замовлення — резервування — оплата — логістика) з механізмами компенсуючих дій у разі виникнення помилок.

## 4. Ключові функції системи (Core Features)
1. **Асинхронна обробка замовлень через Transactional Outbox:** гарантована публікація подій зміни статусу замовлення в брокер без використання розподіленого 2PC-блокування (Two-Phase Commit).
2. **Оркестрація розподілених транзакцій (Saga Pattern):** послідовне виконання етапів оформлення замовлення з автоматичним запуском компенсуючих транзакцій у разі відхилення платежу або дефіциту складських запасів.
3. **Ідемпотентні консюмери брокера повідомлень:** дедуплікація вхідних повідомлень на стороні підписників за допомогою розподіленого кешу ключів ідемпотентності, що усуває ризик повторних транзакцій.
4. **Високопродуктивний сервіс мультивалютного ціноутворення:** динамічний розрахунок локальних податків, мит та конвертації валют на базі in-memory сховища з низькою латентністю (< 15 мс).
5. **Розподілений трасинг та телеметрія подій (Observability):** наскрізна ідентифікація асинхронних запитів за TraceID через сервіси та брокер для виявлення вузьких місць і збоїв.
6. **Автоматизований DevSecOps-контур з контролем якості:** автоматична перевірка коду статичними аналізаторами (SAST), розрахунок цикломатичної складності та сканування образів контейнерів на вразливості CVE.

## 5. Інструментарій та технологічний стек (Technology Stack)
* **Мови програмування:** Go (Golang) — для високонавантажених мікросервісів обробки замовлень і подій; TypeScript / Node.js — для API Gateway та оркестратора бізнес-процесів.
* **Архітектурні патерни:** Event-Driven Architecture (EDA), CQRS, Transactional Outbox, Saga (Orchestrated), Database per Service, Idempotent Consumer.
* **Фреймворки та мережеві протоколи:** gRPC / Protocol Buffers (внутрішньосервісний зв'язок), Gin / Fiber (RESTful зовні), NestJS.
* **Брокери повідомлень та черги:** Apache Kafka (кластер топіків з партиціонуванням за OrderID), Kafka Connect.
* **Бази даних та сховища:** PostgreSQL (реляційне сховище для ACID-операцій мікросервісів), Redis (розподілений кеш, блокування Redlock, зберігання ключів ідемпотентності).
* **DevOps, DevSecOps та Observability:** Docker, Docker Compose / Kubernetes, GitHub Actions (CI/CD), Trivy (Container Vulnerability Scanner), SonarQube, Prometheus, Grafana, OpenTelemetry, Jaeger (Distributed Tracing).
